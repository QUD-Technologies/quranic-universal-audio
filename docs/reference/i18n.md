# i18n

Frontend internationalization for the SPA. **Paraglide JS 2.x** compiles hand-authored message files into per-message tree-shakable functions; a single locale rune + legacy-store mirror drive reactive re-render and `<html dir/lang>`. Currently `en` (base), `ar`, and `ckb` (Central Kurdish / Sorani). This doc is the *what-is* contract; the **`i18n` skill** (`.claude/skills/i18n/`) is the *how-to* (adding a string, localizing a surface, the bidi conventions). Don't restate one in the other.

**Scope.** Arabic ships both *strings* and the **RTL layout**: `ar` flips `<html dir="rtl">` and the chrome mirrors via logical CSS, while time/position-directional surfaces stay pinned `dir="ltr"` islands (see [RTL layout](#rtl-layout)). See [`docs/planning/i18n.md`](../planning/i18n.md) for workflow sequencing and locked decisions.

## Message files — split by area, prefixed flat keys

Messages are **hand-authored** JSON (not extracted from code), one file per locale per area. The `pathPattern` in `settings.json` is an **array**, listing each area dir and `common` **last** so the inlang editor exports new keys into `common` by default:

```
./src/tabs/dashboard/messages/{locale}.json
./src/tabs/timestamps/messages/{locale}.json
./src/tabs/segments/messages/{locale}.json
./src/lib/i18n/messages/common/{locale}.json
```

Keys are **flat, prefixed by area** so the namespace stays collision-free across files: `common_action_save`, `common_auth_sign_in`, `common_signin_edit_title`, … (per-tab files use `dashboard_*` / `timestamps_*` / `segments_*`). Paraglide flattens all files into one global message map, so the prefix *is* the namespace — there is no nesting. Every key MUST exist in **all** configured locales for an area (parity); a test enforces this (below).

Arabic chrome copy is **MSA, no tashkeel** (vowel marks are for Quranic text, not UI labels). Quranic text and reciter names are data, not UI strings — they are never translated (see boundary below).

## Compile + build-order wiring

The repo's `check`/`build` run `svelte-check`/`tsc` **before** Vite, so the generated `src/lib/paraglide/` dir must already exist when type-checking starts. A reusable `paraglide:compile` npm script is chained ahead of every entry point (`inspector/frontend/package.json`):

| Script | What |
|---|---|
| `paraglide:compile` | `npx --no-install @inlang/paraglide-js compile --project ./project.inlang --outdir ./src/lib/paraglide --strategy localStorage preferredLanguage baseLocale --output-structure message-modules --emit-ts-declarations` |
| `postinstall` | `npm run paraglide:compile` — so fresh `npm ci` / CI / worktrees have the dir before anything reads it |
| `dev` / `build` / `check` / `typecheck` | each prefixed with `npm run paraglide:compile &&` |

On `dev`/`build` the **`paraglideVitePlugin`** also recompiles (`vite.config.ts`) — this pass is what stamps the runtime strategy + `localStorageKey: 'insp_locale'` into the bundle.

**Two CLI-vs-plugin facts to know** (the 2.20.1 CLI and the Vite plugin don't take the same flags):
- The CLI has **no `--localStorageKey` flag**, and `--strategy` takes **space-separated** items (not repeated flags). The localStorage key is configured on the **Vite plugin only**; the CLI pass exists purely to materialize the dir for `tsc`/`svelte-check`, and the plugin re-stamps the real runtime strategy/key on `dev`/`build`.
- `--emit-ts-declarations` (CLI) + `emitTsDeclarations: true` (plugin) are **required**: the generated runtime is `.js` with JSDoc, and under this repo's strict `allowJs: false` tsconfig `svelte-check` errors "Could not find a declaration file" for every `$lib/paraglide/*` import without the `.d.ts` companions.

A `$lib` → `src/lib` resolve alias was added in **three** places so the documented `$lib/paraglide/...` import style resolves everywhere: `vite.config.ts` (`resolve.alias`), `tsconfig.json` (`paths`), and `vitest.config.ts` (`resolve.alias` — vitest has its own config; without it the `$lib/paraglide/*` imports fail to resolve in tests).

## Locale rune + dir/lang plumbing

Two reactive mirrors of Paraglide's *ambient* locale, kept in lockstep by one switch:

- **Runes** (`locale.svelte.ts`): `i18n.locale` is a `$state` cell. Reading it in a template or `$derived` registers a dependency; the write on switch trips re-render. Seeded from `getLocale()` (Paraglide's own localStorage → preferredLanguage → baseLocale resolution).
- **Legacy** (`locale-store.ts`): `localeStore` is a `writable`. Legacy Svelte-4 files (e.g. `App.svelte`) re-render off `$localeStore`. Because `tsc` rejects the `($localeStore, m())` comma-operator trick as an unused expression, the bridge helper `tr($localeStore, m_fn())` carries the dependency while returning the string: `$: label = tr($localeStore, common_auth_sign_out());`.

**One switch funnel.** Every switcher routes through `switchLocale(next)` (`locale-store.ts`), which:
1. `setLocale(next, { reload: false })` — updates Paraglide's ambient locale + persists via the localStorage strategy under `insp_locale`,
2. `localeStore.set(next)` — trips legacy subscribers,
3. `runeSetter?.(next)` — trips the runes cell (registered once by `locale.svelte.ts` via `registerRuneSetter`, avoiding a `.ts → .svelte.ts` import),
4. `applyDocument(next)` — sets `<html lang>` and `<html dir>` (`rtl` for `ar` and `ckb`, else `ltr`).

`initLocale()` is called once in `main.ts` before mount (mirroring `installAudioWarmup`) to sync `<html dir/lang>` with the resolved boot locale. Arabic sets `<html dir="rtl">`; the chrome mirrors via logical CSS with time-axis surfaces pinned `dir="ltr"` (see [RTL layout](#rtl-layout)). The direction lives in the `RTL` set duplicated in `locale.svelte.ts` **and** `locale-store.ts` — keep both in lockstep.

## Message consumption

Per-message functions are deep-imported from the generated tree: `import { common_signin_edit_title } from '$lib/paraglide/messages/common_signin_edit_title';` then called `common_signin_edit_title()`. Each call reads the current ambient locale at *access* time. Two consumption shapes are in use:
- **Lazy getters** (`sign-in-messages.ts`) — `title`/`body` getters call the message fn on access, so a modal snapshots copy in the locale current when it opens.
- **`$:` + `tr()`** (`App.svelte`) — legacy reactive labels recompute when `$localeStore` changes.

Runes components read `i18n.locale` directly (e.g. `LocaleSwitcher` for its active-state highlight).

`src/lib/paraglide/` is regenerated on every install/dev/build by its own toolchain (unlike the committed Pydantic→TS schema codegen, this is **never committed**). It is excluded at every gate:

| Exclusion point | File |

## Do / don't translate boundary

| Translate (UI chrome + data vocab) | Never translate (data) |
|---|---|
| Buttons, labels, prompts, modal copy, toasts, empty states | Quranic Arabic text + tashkeel (rendered as-is from the shard/refs) |
| Tab names, filter labels, validation card headings | Reciter names + transliterations (catalog data; `ar`/`en` pairing is a data concern) |
| Riwayah / style / recording-context / coverage enum values (via the **vocab layer**, below) | **Channels + source** (mp3quran, QuranicAudio, tvQuran… stay Latin) and brand/product names (Hugging Face, GitHub, "Qur'anic Universal Audio") |
| Surah names + country names (locale-aware **data selection**, below) | Phoneme glyphs, waqf marks, IDs, slugs, timestamps |

## Locale-aware DATA labels (vocab / surah / country)

Some user-visible strings are DB/data values, not static chrome. They are localized at the **render site** through three helpers — never by rendering the raw value or calling `titleCaseSlug` on it. A value counts as "translated" only when a render site calls the helper; adding a message key alone does nothing.

- **DB enum vocab** — `vocabLabel(kind, value)` (`$lib/i18n/vocab`, impl in `lib/utils/delivery-label.ts`) maps `riwayah` / `style` / `context` / `coverage` slugs to `vocab_<kind>_<value>` messages, falling back to `titleCaseSlug`. The shared label utils route through it (`combinationCompact`/`combinationStandard`, `axis-labels.ts::tagLabel`); the dashboard facet rail translates pills at render in `PickerFilterRail.svelte`. **Channels are deliberately not a kind** — use `channelDisplay()` (`channel_name` ?? `titleCaseSlug`).
- **Surah names** — `surahName(num, locale)` / `surahOptionText(num, locale)` (`lib/utils/surah-info.ts`) pick `name_ar` (stripped of leading "سُورَةُ") vs `name_en`. Pass the active locale at every call site (player, footer, history, bookmarks). Search boxes match against `num + name_en + name_ar` so either script filters.
- **Countries** — `countryName(iso2, locale)` (`Intl.DisplayNames`, per-locale cache), `countryByName(name, locale)` (resolves English name, localized name, OR ISO code), and `filterCountries(query, locale)` (matches code + en + ar) in `lib/utils/countries.ts`. The shared `lib/components/CountryPicker.svelte` combobox uses them; the stored wire value stays the ISO code regardless of display language.
- **Op-type / validation labels** — history op labels via `tabs/segments/i18n/history-labels.ts::editOpLabel`; validation category labels via `tabs/segments/i18n/validation-labels.ts::VALIDATION_TITLE` (keeps `registry.ts::displayTitle` untouched — it is parity-pinned).
- **Guide example cards** — `exampleTitle` / `exampleDescription` / `exampleContextLabel` (`tabs/segments/guides/examples/example-labels.ts`) overlay the **auto-generated** `examples/index.ts` (English `title`/`description`/`context.label` only) with `segments_guide_example_<id>_{title,desc,ctxN}` keys, falling back to the baked-in English. A newly-generated example renders English until its `ar` keys are added.
- **Activity reciter name** — backend `services/activity/public_activity.py` emits `name_ar` on each card; `ActivityRail` prefers it in `ar`, falling back to `name`.
- **Numerals** — `toArabicNumeral` (`lib/utils/arabic-text.ts`) renders ayah numbers (filmstrip cells) and missing-word indices as Arabic-Indic digits under `ar`.

**Reactivity:** these helpers return ambient-locale strings, so on-load is correct automatically. To re-render on a live locale switch, the call site must depend on the locale — runes: read `i18n.locale`; legacy: `tr($localeStore, helper(...))` or reference `$localeStore` in the `$:`.

## Guide bodies (translation-parallel source)

Guide **bodies** are translation-parallel source, not message keys (the modal *chrome* — kicker, close, "Goal" — is keyed as usual):

- Category prose lives in `*.ar.guide.ts` siblings; the About body in `overview.ar.md`; both selected by locale.
- The illustrated editing/flagging bodies are **Arabic sibling components** (`EditingGuideContent.ar.svelte`, `FlaggingGuideContent.ar.svelte`) chosen by `AccordionGuideModal::guideComponent(name, locale)`. Their shared mocks (`MockSegCard` / `ValActionMock`) are locale-aware — they **reuse the real editor's `segments_row_*` keys** so the illustration stays in lockstep with the live buttons — and are pinned `dir="ltr"` so they mirror the still-LTR live editor even inside an RTL guide.

The About + accordion-guide modals also set `dir` on their content container in `ar` (redundant now the global flip covers them, but harmless — kept for the inner `dir="ltr"` island pins).

## RTL layout

`ar` flips `<html dir="rtl">` (via the `RTL` locale set); most chrome mirrors for free because flex/grid reorder under `dir`. Two disciplines make it correct:

1. **Logical CSS, not physical.** Chrome uses `padding-inline-start` / `margin-inline-*` / `border-inline-*` / `inset-inline-*` / `text-align: start|end` — never `*-left`/`*-right`. A physical value silently ships wrong under RTL. Shared stylesheets (`components/validation/history/filters/segments/combination-picker/stats.css`) and component `<style>` blocks were converted; the island rules below deliberately stay physical.
2. **`dir="ltr"` islands.** Any surface whose horizontal axis encodes **time or position** is pinned `dir="ltr"` so it never mirrors: the player + segments-footer **scrubbers** (`PlayerProgress`, `.progress`), all **waveforms** (`WaveformCanvas`, `TimestampsWaveform`, segment-row canvas), **`AyahFilmstrip`**, the **segment editor** rows (`SegmentRow`) + `SplitPanel`/`TrimPanel` nudgers, the **edit-history before→after diff** (`.seg-history-diff` + `HistoryArrows`), and `StateTimeline`. Media **transport** (`PlayerControls` + the footer transport) is pinned LTR by convention (play/seek don't mirror). The **teleprompter** (`LineAnimation`) is *not* pinned — it's Arabic-native text that should flow RTL. `TimedAnalysisRow` inherits the shared renderer's Arabic RTL layout while keeping timing tooltips LTR.

**Direction-aware JS/glyphs** (a few spots CSS logic can't cover): the Report drop-up `keepInView` picks the anchor edge from `getComputedStyle(node).direction`; the `Toggle` knob rides `inset-inline-start` (auto-flips) and the tajweed knob gets a `[dir='rtl']` translate override; the Report-menu disclosure chevron rotates to point the reading direction under `[dir='rtl']`. The submit-wizard step underline (`SubmitWizard`) anchors at `inset-inline-start:0` and negates its `translateX` under `[dir='rtl']` so it tracks the selected step.

**Number localization (`lib/i18n/format.ts`).** Digits are locale-aware, not hardcoded. `localizeDigits(value, locale?)` maps ASCII digits to the ambient locale's set (Arabic-Indic ٠..٩ under `ar`), leaving every non-digit character untouched — so decimals, separators, and units (`1.5×`, `47/114`, `3h 45m`, `192 kbps`) localize in place, and it's a no-op for every non-Arabic locale. Reactivity mirrors `m.*()`: runes read the `fmtNum(n)` sugar (from `locale.svelte.ts`, reads reactive `i18n.locale`); legacy `$:` blocks use `tr($localeStore, localizeDigits(n))`; pure `.ts` builders (`delivery-label.ts`) call it with the ambient default and inherit their consumer's locale reactivity. Applied at the display sites — filter/facet pill counts (`FilterPill`), reciter-row + reciter-detail counts, delivery labels (coverage/hours/bitrate/year), speed multipliers, surah/ayah picker numbers, report counts. The raw digit map is `arabic-text.ts::toArabicNumeral` (the filmstrip's numerals). **Do not** re-add `i18n.locale === 'ar' ? … : …` conditionals at call sites.

**Shared surah picker (`lib/components/player/SurahPicker.svelte`).** The trigger chip + `SurahPopover` dropup are one runes component, used by both the bottom player and the Segments footer (`compact` prop for the denser transport); `open` is parent-controlled so each footer keeps its own click-outside / sibling-popover coordination. No caret glyph — the border + hover signal that it opens.

**Out of scope / deferred:** the entire **admin dashboard** (RTL + its remaining English strings); and a small polish tail — a handful of 4-value `padding`/`margin` shorthands and decorative hover `translateX` nudges. There is **no** automated logical-CSS lint guard yet (an island-aware guard is a separate task); enforce the logical-CSS rule in review.

## Verification / CI

- **`npm run check`** (compile → `svelte-check`) — type-checks every `$lib/paraglide/*` import; passes because of the `.d.ts` companions + the `$lib` alias. Run before pushing.
- **`npm run build`** (compile → `tsc` → `vite build`) — the Vite plugin recompiles and stamps `insp_locale`; verify a localized string lands in both locales in `dist/assets/index-*.js`.
- **`npm run test`** (vitest) — `src/lib/i18n/__tests__/message-parity.test.ts` asserts each area's non-base locale carries **exactly** the base-locale key set (missing *or* extra fails) and every seed file is valid JSON. It reads `project.inlang/settings.json`, so a new area/locale is covered with no edit. This is the **only** thing enforcing key coverage: Paraglide's compiler validates message *syntax* + call-site *types* but silently falls back to `baseLocale` for a missing translation, so without this test a forgotten `ar` key ships English unnoticed.
- No i18n-specific CI job / eslint rule exists — i18n rides the existing FE `check`/`build`/`test` gates (the parity test above runs in `test`). There is **no** automated hardcoded-string guard; catch un-keyed literals in review (see the render-site audit below). The generated dir's exclusions keep it out of lint/coverage/codegen diffs.
- **Render-site audit, not just keys.** A prior pass authored `vocab_*` keys with zero call sites, leaving riwayah/style/coverage/context English everywhere. When localizing a surface, grep every `titleCaseSlug(...)` on a data enum, every raw `name_en`, and every hardcoded label — a key is inert until a render site calls its helper.
- **Runtime smoke in `ar`.** Type-checks don't open modals. Open every interactive surface you touched (modal, picker, dropdown) in Arabic on the running stack before claiming done — the About modal shipped a `each_key_duplicate` crash (Arabic headings all slugified to `''`) that only a runtime open would catch.

## Central Kurdish (Sorani)

`ckb` is Central Kurdish in Arabic script, shown as **کوردی** in the header cycle (Auto → English → عربي → کوردی → Auto). Browser preferences such as `ckb-IQ` resolve to `ckb`; a generic `ku` tag is not mapped to Sorani because it can mean another Kurdish variety. Locale pinning persists under `insp_locale`.

Sorani ships every configured message area, all 14 accordion guide sources (including the low-confidence alias), the illustrated editing/flagging siblings, the About document, and all three mark-ready documents. Document discovery accepts two- and three-letter locale codes. Source directives, example ids, audio references, checklist section ids, and lifecycle keys stay unchanged. Quran text stays source data; surah and reciter display names prefer the stored Arabic-script name, with the existing English fallback. Arabic-Indic digits apply to Sorani display strings too; ids and timestamp inputs retain their wire format.

Sorani uses the existing RTL chrome and LTR time-axis islands. Split **دابەشکردن**, merge **یەکخستن**, reference **ئاماژە**, undo **هەڵوەشاندنەوە**, discard **وازهێنان**, waṣl **وەسڵ**, and waqf **وەقف** are consistent between controls, history, examples, and guides. Numbered counts use the same natural Sorani noun form for singular and plural, with the count preserved. The admin dashboard retains its previously deferred English copy.

The localisation tests check message input preservation, actual Sorani guide/document selection (so a silent English fallback fails), preserved example/component directives and lifecycle states, and RTL locale cycling/persistence.
